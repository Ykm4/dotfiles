# 外部コマンドの繰り返し起動

通信する外部コマンド（`gws`・`gh`・`curl`など）を、`xargs`・`for`・並列実行で項目ごとに起動する作業が対象である。件数が少ないときも適用する。サブエージェントとワークフロー配下のエージェントにも適用する。

---

## 起動の頻度

- 再試行を含め、項目ごとの起動は毎秒4回以下にする。
- 既定は逐次実行とし、各コマンドの完了後に`sleep 0.25`を入れる。
- 並列は使わない。`xargs -P`や各ワーカーの`sleep`では、全体の起動間隔を保証できない。
- 並列が必要なときは、実行前にユーザーへ理由と並列度を伝える。
- 最初の30件を流した後に一度、下のコマンドで自分の`trustd`のCPUを確かめ、30%を超えていたら止めてユーザーに報告する（確認に失敗したときは、逐次実行のまま進める）。
- 起動予定が2,400回（毎秒4回で10分）を超えるとき、または処理時間を含めて10分を超える見込みのときは、先に1プロセスで複数項目を処理する方法（APIの一括取得、接続を使い回すスクリプト）を探す。

```bash
ps -Ac -o uid=,%cpu=,comm= | awk -v u="$(id -u)" '$1==u && $3=="trustd" {print $2}'
```

## 重複の防止

- 同じ作業は1つのジョブにまとめ、サブエージェントへ分けて並行させない。
- 開始前に`pgrep -x <コマンド名>`で同じコマンドが動いていないか確かめ、終了値0なら終わるまで待つ。
- `pgrep`は補助であり、失敗（終了値2や3）や一致なしだけでは「動いていない」と判断せず、実行ツールのジョブIDなどで他のジョブを確かめる。

## 根拠

2026-10-11に、`xargs -P 12`で対象約5,354件について、`gws`のAPI取得を繰り返し起動した。5秒間に少なくとも88回起動し（毎秒17.6回以上）、次の症状が出た。

- ユーザー側の`trustd`のCPUが約96〜98%になり、ジョブの終了後は増分0に戻った。
- Raycastが8分以上ウィンドウを出さなかった。
- `mdfind`とAppleScriptが応答しなかった。

起動の頻度と負荷が比例するかは未検証で、API呼び出し1回あたりの負荷も未測定である。`curl`の逐次40回と`gws --version`の逐次100回では、`trustd`のCPU増分は0だった。

毎秒4回と30%は、上の1件を参考に選んだ暫定の基準であり、安全を測った値ではない。測り直したら直す。
