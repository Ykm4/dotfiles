# 実装計画・仕様書を図解する

実装計画は「順序」「依存」「境界」を含むのに、Markdownではそれが文章に溶ける。図にすると読む前に構造が掴める。

## 元になる計画を特定する

引数でパスが渡されていればそれを読む。渡されていなければ、この順で探す。

- 直前の会話で書いた計画
- `docs/superpowers/plans/`配下の最新ファイル
- `specs/` `plans/` `docs/plans/`配下の最新ファイル

見つからなければ、どの計画かを尋ねる。推測で進めない。

計画と対になるspecが`docs/superpowers/specs/`にあれば、そちらも読む。背景と判断理由はspec側にあることが多い。

## 見出しの階層を実ファイルで確認する

superpowersのテンプレートは`### Task N:`だが、実ファイルが`## Task N:`を使っていることがある。`grep -F -n '# Task' <file>`で実際の階層を確かめてから解析する。テンプレートの想定を実ファイルに当てはめない。

## 図の型を内容から決める

計画に書かれている構造だけを図にする。無いものを描き足さない。

| 計画にあるもの | 図の型 | 手段 |
|---|---|---|
| ファイル構成・責務の分割 | ツリー | Mermaid `flowchart TD` |
| タスクの前後関係 | 依存グラフ | Mermaid `flowchart LR` |
| 処理の流れ・APIの往復 | シーケンス | Mermaid `sequenceDiagram` |
| 状態遷移 | 状態機械 | Mermaid `stateDiagram-v2` |
| データ構造 | ER | Mermaid `erDiagram` |
| システムの構成要素 | 構成図 | Mermaid `architecture-beta` |
| 積み重なる層・責務の分離 | レイヤー | Mermaid `block-beta` |
| タスクの進行状況 | ボード | Mermaid `kanban` |
| 施策の優先度 | 4象限 | Mermaid `quadrantChart` |
| 日程だけ | ガント | Mermaid `gantt` |
| 日程 + 見積りなどの数値 | 数値列つきガント | `parts.md`の部品 |
| 段階的な積み上げ | 階段・ステップ | `parts.md`の部品 |

並行できるタスクは`flowchart LR`で横に並べる。直列に見せない。

`block-beta`は`columns N`でグリッドを作り、`block:ID:N`でネストと列スパンを指定する。層を積むときに使う。

```
block-beta
  columns 3
  ui["UI 層"]:3
  block:core:2
    columns 2
    parser["parser.ts"]
    mapper["mapper.ts"]
  end
  store["store.ts"]
```

## 本体を組む

以下は型であって、内容に合わなければ変える。

- 全体像の図を1つ。読者が最初に見るのはこれ
- タスク一覧の表。依存・見積り・完了条件。状態は`.chip`で示し、色だけに頼らない
- 各タスクの詳細。長ければページ内アンカーで飛べるように
- 未決事項とリスク。無ければ節ごと省く

## 固有の自己点検

`authoring.md`の点検に加えて確認する。

- 図のノード数が15以下であること
- 計画に無い設計判断を図に混ぜていないこと

## 注意

- 図は計画の写像であって、計画の続きではない。
- タスクの粒度や順序に疑問があれば、作図の前に指摘する。
- 図にすると誤りが構造として固定される。
