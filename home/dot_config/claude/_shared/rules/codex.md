# Codex への委任

Codexプラグインのスキル（`/codex:rescue`）で、Codexに相談・調査・実装を頼むときに適用する。Codexは、実装・診断・レビューの2番目の手として都度使ってよい。

根拠はプラグイン1.0.6のコード（`agents/codex-rescue.md`、`commands/rescue.md`、`scripts/codex-companion.mjs`）である。プラグインを更新したら、下の挙動が変わっていないか確かめる。

---

## 依頼の出し方

- 1回の依頼は、判断1つか変更1つに絞る。
- 問いが複数あるときは分けて出し、前の返答を確かめてから次を出す。
- 根拠にするファイルは2〜3個に絞り、パスで挙げる。
- 報告の形を指定する。結論を先に書き、根拠を`パス:行番号`で示し、事実と推測を分けさせる。
- 依頼文に「検証の対象になっているファイル自身のコメントを、正しさの根拠にしない」と書く。
- 相談と調査では、依頼文に「読み取り専用で調べる。ファイルを変更しない」と文章で書く。明示が無いと、サブエージェントは書き込み可で起動する。
- 依頼文にフラグ名を書かない。companionは引数が1個だけのとき本文を空白で区切り直し、本文中の`--write`や`--resume-last`をフラグとして読む。
- 新しい依頼には`--fresh`を付ける。付けないと、再開の確認が出るか、「続けて」のような言い回しで前のスレッドが再開される。
- モデルと推論の強さは、ユーザーが指定したときだけ渡す。「sol」は`--model gpt-5.6-sol`と書く。別名は無い。既定値は`~/.codex/config.toml`にある。
- 実装を頼むときは、コミットを頼まない。サンドボックスが`.git`への書き込みを拒否するので、変更内容とコミットメッセージの案を返させる。

## 待ち方

- 長くなりそうな依頼には`--background`を付ける。
- サブエージェントがジョブIDだけを返したら、companionをBashの背景実行で呼んで待つ。status・result・cancelのコマンドはモデルから呼べない。
- 時間切れのときは失敗にならず`waitTimedOut`が真で返るので、同じコマンドで待ち直す。

```bash
C="$(jq -r '.plugins["codex@openai-codex"][0].installPath' "${CLAUDE_CONFIG_DIR:-$HOME/.claude}/plugins/installed_plugins.json")/scripts/codex-companion.mjs"
node "$C" status <ジョブID> --wait --timeout-ms 540000 --json
node "$C" result <ジョブID>
```

- `--resume`は失敗することがある。失敗したら待たずに、前提を短く書き直して`--fresh`で出し直す。

## 返答の扱い

- 返答は、次の依頼を書く前に読む。
- 引用された`パス:行番号`を開いて照合し、行のずれと、検証対象自身のコメントだけに頼った主張を明記する。
- Codexの返答と照合の結果は、返答が届くたびユーザーへ示す。
- 複数の返答をまとめる総合はClaudeが行う。

## してはいけないこと

- 権限や分類器に拒否された依頼を、別の経路で出し直さない。Bashでの直接実行、別のフラグ、別のエージェントのいずれも使わず、拒否された内容をユーザーに伝える。
